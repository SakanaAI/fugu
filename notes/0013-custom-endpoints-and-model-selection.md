Custom endpoints and install-time model selection

Fugu installs continue to use https://api.sakana.ai/v1 and fugu-max by default, with no new prompt. To target a dev or self-hosted service, run install.sh with --base-url URL, or set SAKANA_BASE_URL on a fresh install or together with --reconfigure; the URL is checked before Codex is installed or switched, normalized, rendered into the provider configuration and stored securely alongside the API key. Any spelling of https://api.sakana.ai/v1 counts as production, and a plain http:// endpoint that is not local prints a warning. To move to another endpoint and rotate its key together, run install.sh --set-key --base-url URL (or codex-fugu --set-key --base-url URL). Choose a catalog model with --model, or use FUGU_MODEL on a fresh install or with --reconfigure; the choice is kept across updates until --model default returns to the bundle default. Only explicit endpoint and model overrides are pinned, so future production defaults continue to reach users who did not opt out. A custom endpoint applies to Codex only: claude-fugu keeps using production unless CLAUDE_FUGU_BASE_URL is set.

Existing automated, curl-piped and key-only installs remain non-interactive; on a terminal, --reconfigure also offers the saved endpoint. Ordinary updates ignore SAKANA_BASE_URL and FUGU_MODEL from the environment and print a warning naming --base-url / --model (none for a SAKANA_BASE_URL that is already the endpoint in use), including the first update run by an older launcher, so unrelated shell settings cannot become persistent choices. The installer records the custom endpoint it saves in ~/.codex/.fugu/state and honours only that SAKANA_BASE_URL line in ~/.codex/.env (or, with no record yet, a line naming the same custom URL as Fugu's provider block, which it then records); a line it did not write, such as one added for another tool, is ignored with a warning and left in place. codex-fugu --status now shows the default model (pinned or bundle default) and the API endpoint. Credentials are validated before configuration changes, rejected values are never printed, dotenv values are parsed without execution, and a saved model that is no longer in the catalog warns and falls back to the current bundle default instead of blocking an update or rollback. If you keep your own [model_providers.sakana] table, its endpoint stays in effect and your key is still stored (in the production format unless --base-url, or SAKANA_BASE_URL with --reconfigure, naming that table's URL saves it); only an explicit endpoint change stops until you merge that table.
