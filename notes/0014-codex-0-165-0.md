Codex is now pinned to 0.165.0

Fugu now targets Codex 0.165.0. The launcher will offer to switch your Codex to it, and your existing Fugu configs, API key and endpoint carry over unchanged.

This spans three upstream releases (0.163 through 0.165): /config searches your preferences and applies supported changes immediately, /keymap gains a leader key (Ctrl+X by default), ten numbered /presets slots hold reusable prompts, /model and /permissions accept their settings inline, terminals with Kitty or Sixel graphics preview images in the fullscreen transcript, and the session picker can filter by repository. Resuming a session now restores its saved settings and permissions, a failed compaction no longer leaves a partial summary behind, -c overrides are kept when they appear at more than one subcommand level, queued agent messages no longer restart work after an interrupt, and a model the server reports as not found now fails at once with the server's message instead of being retried.

Nothing is required on your part, and your Fugu models and settings work as before. Codex 0.164.0 stopped reading the worktrees and voice settings that Fugu pinned off, so ~/.codex/fugu.config.toml now carries a disabled placeholder entry, [mcp_servers.codex_worktrees], that keeps Codex's local worktree tools out of Fugu sessions as before; it is never started and shows as a disabled server in /mcp. Launching with --enable worktrees no longer brings the worktree tools back, and removing that table by hand lasts only until the next update replaces the file. /voice may now appear among the commands, but the Fugu API does not offer realtime voice, so it does not work in Fugu sessions.
